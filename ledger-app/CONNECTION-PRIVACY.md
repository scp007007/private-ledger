# 连接排查与账单隐私（0.3.2）

## 手机连接电脑

APK 是客户端，电脑上还需要运行账本服务。电脑与手机接入同一网络后，仍要满足：地址正确、服务监听该地址、TCP 8000 允许从手机所在网络访问。

### 本机最快启动方法

1. 双击项目 `outputs/start-ledger-server.cmd` 打开“私有账本 · 电脑端”。它自动选取优先的局域网网卡，排除代理和常见虚拟网卡；有多个候选时，可从下拉框选择手机能访问的网卡。
2. 首次配置时，若手机已有令牌，在隐藏输入框中填写原令牌；留空会生成新令牌。点击“启动服务”，等到窗口显示“服务就绪”。以后启动会复用 Windows DPAPI 加密保存的令牌，不必重新生成。
3. 点击“复制地址”，在手机填写服务器根地址，使用 HTTP 时确认网络可信，点击“先检查网络（无需令牌）”。这一步只请求 `/health`，不发送令牌或账单。
4. 网络检查通过后，在电脑点击“复制连接令牌”，将令牌传到自己的手机并粘贴，点击“连接并同步账本”。令牌验证成功后才会保存连接及离线副本。请勿将令牌发给他人。

电脑端窗口最小化后服务继续运行；关闭窗口会提示停止服务。电脑休眠、断网或服务停止时，手机保留已有离线数据。换网络后 IP 可能改变，应重新打开电脑端取得当前地址；旧地址不会自动变成新地址。

主账本默认继续使用 `%LOCALAPPDATA%\PrivateLedger\ledger.sqlite3`，不会清空已有流水。令牌位于同目录的 `api-token.dpapi`，由当前 Windows 账户和电脑保护。原来使用自定义 `LEDGER_DB_PATH` 的用户仍须在每次启动环境中设置该路径；脚本不会擅自迁移数据库。更换电脑时，DPAPI 文件不保证能解密，需保留原令牌或重新设置并更新客户端。

源码包用户先按 `server/README.md` 安装依赖，然后在该目录执行 `powershell -NoProfile -STA -ExecutionPolicy Bypass -File .\ledger-desktop.ps1`。原 `start-ledger-server.ps1` 仍提供命令行启动方式。

### 超时的定位方法

双击 `outputs/check-ledger-connection.cmd`。它只检查网卡、监听状态和不带令牌的 `/health`，不读取账单或访问令牌、不改防火墙。

| 检查结果 | 下一步 |
| --- | --- |
| 手机网络检查通过，但令牌验证失败 | 手机已能访问电脑。在电脑端复制相同令牌后重试；不必为此修改防火墙。 |
| 手机网络检查失败 | 先看电脑是否显示“服务就绪”，再核对手机填写的是电脑当前地址。 |
| 电脑也打不开 `/health` | 先检查启动窗口是否还在运行、有无报错，以及地址和端口是否一致。 |
| 只监听 `127.0.0.1` | 这是电脑本机地址；停止旧服务，用启动脚本选择局域网地址。手机不能靠填写 `127.0.0.1` 访问电脑。 |
| 电脑能打开、手机超时 | 检查手机是否在访客 Wi-Fi、路由器是否启用设备隔离、电脑和手机的代理/VPN是否拦截局域网，再检查 Windows 防火墙。 |
| 手机浏览器成功，应用返回 401 | 网络已通，核对令牌；重启服务后应复用同一令牌。 |
| 应用报告跳转或证书错误 | 核对最终 HTTPS 根地址和证书配置；应用不会跟随跳转携带令牌或文件，也不会跳过证书验证。 |

需要防火墙规则时，只允许可信私人网络、相应本机地址和 TCP 8000，并限制来源到实际可信网段。保持防火墙开启，不把 HTTP 端口映射到公网。Windows 网络被标记为“公用”时，不要为了连接账本盲目放宽所有网络的权限。

## 支付宝、微信账单如何处理

当前通过用户手动选择官方导出的 CSV/TXT/ZIP 导入，尚未接入支付账户自动读取接口。应用无需支付宝或微信密码、验证码、Cookie；源码中没有自动上传账单给外部 AI 的功能。用户选择的文件发送到**自己填写的服务器地址**，并在该服务器解析。

0.3.2 已包含的保护措施：

- 所有数据 API 校验访问令牌。同步只返回账本需要的字段，不返回 `raw_json`。
- 新导入只保留已识别的记账字段，不保存未使用的附加列，例如额外的对方账号、银行卡号列。商户、描述和备注本身仍可能含隐私，需要用于查账的内容不会自动抹去。
- 提交后清空预览中的流水副本，保留提交结果以支持安全重试；未提交预览 24 小时后失效，在下次启动、预览或提交时清理。空闲时没有后台定时擦除。
- 错误响应和手机连接、同步、导入、导出错误提示避免回显原始账单、无效输入或服务器错误正文。启动器关闭常规 HTTP 访问日志。
- 客户端禁止 API 重定向，避免令牌或账单被转发；HTTPS 保持默认的证书校验。
- API 响应带 `Cache-Control: no-store`，减少中间缓存；手机仍有有意保留的离线副本。
- Android 配置禁止应用云备份和设备迁移，令牌使用系统安全存储。iOS 工程的备份与安全存储配置尚需真机验证。

### CSV 脱敏范围

| 字段 | 脱敏导出 |
| --- | --- |
| 商家、描述、外部交易号、标签、备注 | 清空 |
| 自定义分类 | 替换为“分类1、分类2”等，同一文件内保持分组 |
| 流水 ID 与退款关联 ID | 每次导出临时重编号，同一文件内保持关联 |
| 日期、金额、收支、来源、交易类型、排除状态 | 保留，供分析使用 |

脱敏不等于匿名：金额、日期和交易组合仍可能识别个人。分享前需要自行检查。类别别名和记录标识只在本次文件内有效，不能用于跨次导出关联。完整导出仍保留原信息。导出文件不会由本应用自动发送给外部 AI；是否分享、分享给谁由用户决定。

### 仍需了解的边界

- 普通 HTTP 不加密令牌与账单，即使地址属于私有网段也一样。需要传输保密时用 HTTPS 或已加密的私人 VPN；外出同步也需要相应配置。
- 手机和电脑 SQLite 目前没有应用级数据库加密。设备解锁、文件访问权限、磁盘加密和备份位置仍影响数据保密性。
- 清理预览是数据库逻辑删除，不是对 SQLite 空闲页、WAL、旧备份或用户原始导出文件的安全擦除。既有交易的 `raw_json` 不自动改写。
- 用户导出的 CSV、原始支付宝/微信文件和备份需自行保管；应用不能撤回已经分享的文件。
- 尚无支付宝、微信真实脱敏样本，各版本表头与特殊交易仍待校准。
